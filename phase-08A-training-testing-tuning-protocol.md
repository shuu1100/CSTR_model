# Cross-Phase Addendum — Training, Testing, Splitting and Tuning Protocol

For each task create a task card: target, prediction time, allowed inputs, units, independent sample unit, intended use and forbidden features. Extract/validate data with hashes, column dictionary and exclusions. Split synthetic data by trajectory; experimental data by run; single run by chronological blocks and possible gap. Fit preprocessing on train only. Start with naive and mechanistic baselines, then interpretable ML, then neural models only if justified. Define primary metric/search space before tuning; log every trial, seed, version and runtime; early-stop on validation. Freeze pipeline before final test. Report MAE/RMSE/R² when meaningful, per-trajectory/horizon errors, steady-state and physical residuals, worst cases, runtime and seed variability. For classification include per-class precision/recall/F1, macro-F1, confusion matrix, false alarms/missed detections. Optional fault diagnosis requires explicit taxonomy and labels; never invent labels from unlabeled arrays. Each experiment must output task/dataset cards, source hashes, split manifest, leakage assertions, baseline table, tuning log, curves, locked-test report, physical diagnostics, model card and reproduction command.
